## Measurement B: JDK 25 `javac --release 8` throwaway compile

### Command

```
javac --release 8 -Xlint:all -Xmaxerrs 2000 -d b5ccg/scratch/jdk25-out
  @(find b5ccg/src -name "*.java" | tr '\n' ' ')
```

Result: **170 errors, 100 warnings** (exit 1). The 170 errors are **entirely
B5-0010-in-progress-rename defects** (`Race` / `Loyalty` type name clashes,
`cannot find symbol getRace()`, `cannot be converted to Loyalty`), NOT toolchain
incompatibilities. The 100 warnings are toolchain-source-level observations:

| Warning type | Count | Description |
|---|---|---|
| `options: source value 8 is obsolete` | 2 | `--release 8` flagged as obsolete on JDK 25 |
| `serial` | 40 | Serializable classes without serialVersionUID |
| `rawtypes` | 18 | Raw types in generics (Java 6 era) |
| `cast` | 15 | Unchecked casts |
| `unchecked` | 14 | Unchecked operations |
| `dangling-doc-comments` | 10 | `/**` in Java 5 style; use `/**` (Java 7+) |
| (others) | 1 | mix-of-polymorphic-call, etc. |

### JDK 25 `--release 25` (native mode, no compat flag) comparison

```
javac --release 25 -Xlint:all -Xmaxerrs 2000 -d b5ccg/scratch/jdk25-out25
  @(find b5ccg/src -name "*.java" | tr '\n' ' ')
```

Result: **78 errors, 0 warnings** (exit 1).

- 0 obsolete-option warnings (since 25 is the current JDK) — the 2 `obsolete`
  warnings seen under `--release 8` are the ONLY toolchain-level warnings.
- The 78 errors are reduced from 170 because `--release 25` uses the native type
  system (Race/Loyalty as nominal types) rather than the Java 6 era's
  identity-based enum/const handling. The remaining errors are genuine rename
  defects still in flight from B5-0010.

### Conclusion: JDK 25 `--release 8` T1.0 finding

JDK 25 `--release 8` produces the same code that JDK 8 would produce, plus the
expected 2 obsolete-option warnings (which are benign and suppressed by
`-Xlint:-options`). The 170 errors are entirely from the in-progress B5-0010
rename, not from JDK 25. Zero Java 8+ API usage in the source.
