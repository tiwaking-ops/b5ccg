final comparison is against `docs/RULE_INDEX.md`, a `docs` write, and B5-0043's row
named only `engine,tooling`. A row may claim only the scopes it names, so the work
was split rather than the claim quietly widened.

it is not.

## The "do not fix" note was actively dangerous

The pin record said a commit that normalised the working tree to the blob "would
break the pin; update the pin deliberately or new hash + probe constants + this
note or not at all." That forbade exactly the repair B5-0043 performed, and the
next agent to read it would have been steered away from the fix. The correction
keeps the instruction and inverts what it applies to.

The file now has no CRLF at all, so the count is moot, but the record was wrong.
