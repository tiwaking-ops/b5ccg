## 3. What B5-0034 delivered

The full report is

**The data.** `b5ccg/resources/effects/effects-groups-v1.json` - 35 entries
over all 26 group titles, Deluxe text governing (D5), each entry's

**The vocabulary the pilot forced** (four gaps, all now closed). **The
headline number: with the v0 registry as B5-0028 left it, only 16 of the 26
group cards (61.5%) could be expressed - below the gate's 70% - so the v0
schema would have FAILED the Groups pilot. Ten cards could not be

because the operation shape could not say "may", four because the registry
had no primitive for them, and one because the escape hatch was empty.

1. `CONFLICT_TYPE_PSI` added to the trigger vocabulary - the rulebook names
   four conflict types and the v0 named three.
2. `DAMAGED_CHARACTERS_AT_MOST` added to the condition vocabulary - every v0

3. The operation shape gained an `optional` flag - the rulebook's "may"
   against its "must". The canonical renderer marks a permitted operation

4. Three primitive families: `INFORMATION` (`REVEAL_HAND`, `VIEW_HAND`,
   `REORDER_DRAW_PILE`), `ROTATION` (`ROTATE_TARGET`, moved there from

## 5. One thing a new session must know: this tree is shared

**Another agent was working in the same tree during this session** -
`opencode-space-bunny-free-01`, row **B5-0026** (docs, tooling), a live
claim from 09:33. Two rows touched `compile.sh` and `docs/DECISIONS.md` in
the same hour, and the tooling has **no scope-overlap check**: this row's
claim was taken while that row held `docs,tooling`, and the claim tool
allowed it.

**The cost was paid once, visibly.** The other row's gate capture at 09:52
(`GATE-B5-0026.txt`) is RED, and it is red because of *this* row's in-flight
changes - the v0 effect probe's entry count while the five group cards were
being moved. Nothing was lost, but another row's evidence file carries a
failure that was not its own. That is what the scope-guard row
(**B5-0048**) is for.

**The lesson this row applied.** The red-then-green states were produced in
an **isolated copy of the tree** (`%TEMP%\opencode\redtree`), not in the
shared one, so that a red tree never landed in another row's gate log. The
green state is the real tree. If you work here again, check for other
agents' claims before you take one - `ledger-query.ps1 -Status OPEN` shows
the claim owner, and the claim file's mtime plus its TTL is the liveness
signal.

## 7. Quick-start for a new session

```powershell
Set-Location 'C:\temp\projects\b5ccg'
$jdk='C:\temp\projects\b5ccg\b5ccg\scratch\jdk25-win\jdk-25.0.4.1+1'
$env:PATH = "$jdk\bin;C:\Program Files\Git\usr\bin;" + $env:PATH

# 1. state, and WHO ELSE IS IN THE TREE
git status --short
git log --oneline -3
powershell -NoProfile -File .agent/tools/ledger-query.ps1 -Status "OPEN"
Get-ChildItem '.agent\CLAIMS' -Filter '*.json' | Where-Object { $_.Name -notmatch 'RELEASED' }

# 2. heartbeat (always pass the real javac; the default is the JDK 8 stop condition)
& .agent\tools\new-heartbeat.ps1 -AgentId '<agent-id>' `
   -CurrentTask '<task>' -State active -Javac 'javac 25.0.4.1'

# 3. claim (in-process, with a real array)
& .agent\tools\new-claim.ps1 -TaskId 'B5-0035' -AgentId '<agent-id>' `
   -Scope @('engine','tooling','resources','docs')

# 4. the gate  (must be run from b5ccg/)
Set-Location b5ccg
$env:RUN_TESTS='1'
& sh compile.sh          # 38 classes + 4 tooling probes, ~340s, exit 0

# 5. close out
& .agent\tools\flip-ledger.ps1 -Id 'B5-0035' -NewStatus DONE `
   -AgentId '<agent-id>' -DryRun   # inspect first
#   ... then for real; it does NOT fill the Report column - fill it by hand, CRLF preserved
```

**Do not forget:** `out/` must be wiped between builds when proving
red-then-green; `javac` exit and probe exit are recorded separately; the
cost-audit probe needs `resources/` copied into `out/`; a probe that a change
would break must be shown **red without the change** before the change is
committed - and the red state must be one the probe can actually distinguish.
**And in this shared tree: do not leave the tree red while another agent's
gate is running.**
